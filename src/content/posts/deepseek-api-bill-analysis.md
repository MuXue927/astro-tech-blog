## 引子：从四个月的 ¥0 到一个月 ¥317

我的 DeepSeek API Key 很早就建好了，但充值记录里有两笔钱一直躺着没动：2026-07-04 的 ¥10，和 2026-09-18 的 ¥20。此后近四个月，消费为零——舍不得用。

10 月 11 日起情况变了：一个项目需要重度跑 agent 任务，我正式开闸。到 10 月 25 日，官网「用量信息」页显示累计消费 **¥317.12**、本月消费 **¥307.40**（截图导出时刻的快照值）。本文用两份官网导出的 CSV 逐行重算，把这笔钱拆到分位级，并回答三个问题：

1. 这 300 块到底花在哪了？（答案很反直觉）
2. 账单能不能对平？（能，误差为 0，有一处 ¥0.21 残差如实说明）
3. 顺手核实了最近到处「免费」的 GLM-5.3-Flash，并给出与 DeepSeek V4.1 Flash 的选型结论。

> 证据来源：官网导出的 `amount-2026-10-01_2026-10-25.csv` / `cost-2026-10-01_2026-10-25.csv` / `amount-2026-09-26_2026-10-25.csv` / `cost-2026-09-26_2026-10-25.csv`（近 30 天窗口即本次全部使用记录，首笔消费发生在 2026-09-28，¥0.3481）、官网充值账单与赠送账单截图。下文所有数字均由这四份 CSV 实算得出，验证脚本见文末。

## 二、钱去哪了：读便宜、想贵、说更贵

把 tokens 按 DeepSeek 的三种计费类型拆开（单价 × 用量逐行计算）：

| 计费类型          |        Tokens | Tokens 占比 | 花费 (CNY) |   花费占比 | 实测单价（¥/百万 tokens） |
| ----------------- | ------------: | ----------: | ---------: | ---------: | ------------------------- |
| 输入 · 缓存命中   | 6,763,235,072 |  **98.87%** |     159.21 | **51.68%** | 0.02 / 0.04               |
| 输入 · 缓存未命中 |    63,112,473 |       0.92% |      79.81 |     25.89% | 1 ~ 2                     |
| 输出              |    14,388,649 |   **0.21%** |      69.20 | **22.43%** | 4 ~ 8                     |

![读便宜、想贵、说更贵：0.2% 的输出 tokens 花掉了 22.5% 的钱](/images/deepseek-token-vs-cost-share.png)

三个结论：

- **缓存命中率 99.1%**（输入中命中占 67.63 亿 ÷ 72.64 亿）。这是整份账单的支点：命中价与未命中价差 **25~50 倍**，67.6 亿 tokens 的「读」由它撑起。
- **输出 tokens 只占总量 0.21%，却贡献了 22.43% 的花费**。生成是 API 里最贵的动作。
- 同类计费出现两挡单价，对应错峰时段折扣，且两挡都有真实用量。

记住这句话就够了：**读便宜、想贵、说更贵**。成本优化的第一杠杆不是换套餐、蹲折扣，而是「让重复的前缀走缓存，让模型少说废话」。

缓存命中机制本身不神秘：服务端按请求**前缀**建缓存，下一次请求若开头与之前连续重合，重合部分按命中价计费；**一个字符的改变就把该字符之后的所有内容打回未命中价**。由此落到三条可执行的操作：

1. 固定内容（系统提示词、工具定义、常驻文档）放最前，且不改；
2. 可变内容（日期、随机数、进度）放最后；
3. 批量任务挪到错峰时段跑。

## 五、免费≠长期免费：GLM-5.3-Flash 各渠道核验

在考虑把部分负载迁移到「免费」的 GLM-5.3-Flash 之前，我逐条核实了各渠道的官方条款（核验时间 2026-10-25）：

| 渠道                                          | 官方事实（2026-10-25 核验）                                                               |
| --------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 官方 API 标价                                 | 输入 $0.15、输出 $0.50、缓存读取 $0.03（百万 tokens）；发布期五折**已于 2026-09-09 结束** |
| ZCode / AutoClaw 夜间畅用（23:00–09:00 免费） | 限时活动 2026-09-03 ~ **2026-10-07，已结束**，官方未见延续公告                            |
| 华为云码道「码力续航计划」每日 10M tokens     | 活动中，**官方未公布截止日期**                                                            |
| OpenCode 等平台挂出的 "Free" 档               | 平台与厂商的合作安排，**无任何长期免费条款**                                              |

结论：**「现在免费」≠「承诺长期免费」**。免费期拿来用没有问题，但不应把不可中断的重度工作流绑在上面。

顺带给出若转收费的参考口径（约按 7.2 折算人民币）：

| 组件             | DeepSeek V4.1 Flash（高峰/低峰） | GLM-5.3-Flash（官方标价） |
| ---------------- | -------------------------------- | ------------------------- |
| 输入（未命中）   | $0.30 / **$0.15**                | **$0.15**                 |
| 输入（缓存命中） | **$0.006 / $0.003**              | $0.03                     |
| 输出             | $1.20 / **$0.60**                | **$0.50**                 |

关键差异在缓存命中价：DeepSeek 极致便宜（约 ¥0.02~0.04/M 实测），**对像本文这种 99% 命中的形态，DeepSeek 长期更划算**；反之缓存率低的负载，GLM 的输入/输出标价更友好。

## 七、结论：按任务派活，而不问「谁更强」

我最终落到自己工作流上的分发方式：

1. **DeepSeek V4.1 Flash（付费）**：严密数学推导与 LP/MIP 建模、算法类推理、需要严格口径的论文级输出、长链路 agent 任务。
2. **GLM-5.3-Flash（免费期）**：视觉 coding（看截图自检）、前端/UI 复刻、PPT/文档类成品交付；保持「随时可能转收费」的心理预期。
3. **无论用谁，成本杠杆都一样**：压缓存命中率 + 错峰时段 + 控制输出量。这份账单之所以是实付 ¥211 而不是名义上的 ¥307，靠的正是 99.1% 的命中率和平台的赠送额度。

## 附：复现方法

官网「用量信息」页按时间维度导出 CSV（`amount-*.csv` 按「单价 × 数量」给出用量明细，`cost-*.csv` 给出日 × 模型 × 钱包类型的净费用），逐行重算即可：

```python
import csv
from collections import defaultdict

days = defaultdict(lambda: defaultdict(float))
tokens = defaultdict(int)
est = 0.0
with open("amount-2026-10-01_2026-10-25.csv", newline="", encoding="utf-8-sig") as f:
    for r in csv.DictReader(f):
        if r["type"] == "request_count":
            continue
        est += float(r["price"]) * int(r["amount"])
        tokens[r["type"]] += int(r["amount"])
with open("cost-2026-10-01_2026-10-25.csv", newline="", encoding="utf-8-sig") as f:
    for r in csv.DictReader(f):
        days[r["start_time_iso"][:10]][r["wallet_type"]] += float(r["cost"])
# 预期：est == sum(days) 逐分一致； Paid+Granted 按窗口口径归总
```

本文的核对基线：本月窗口重算 307.676128 = cost 合计 307.676128；近 30 天窗口重算 308.229301 = cost 合计 308.229301（逐行求和，浮点求和顺序一致时误差为 0）。核验时间 2026-10-25 14:43 +08:00，快照差异（页面中的当日数字持续增长）以导出时刻为准。
