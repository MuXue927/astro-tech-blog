你好，欢迎来到我的技术笔记。

我是一个运筹优化（Operations Research, OR）方向的管理科学与工程硕士，日常和整数规划、列生成、启发式算法打交道，也对机器学习、深度学习和 AI Agent 保持长期兴趣。这个站用来存放我在这些方向上那些「值得写下来」的东西。

## 我在做什么

手上的主线是供应链优化：从单周期配送的整数规划模型，到生产驱动的多周期库存与配送问题，中间穿插列生成、自适应大规模邻域搜索（ALNS）这类算法，以及 Python / Gurobi / CPLEX 的实现与对比实验。

但比具体问题更让我在意的，是**代码与结果的可信度**。我在重构论文代码的过程中发现过一个很典型的问题：全局车辆编号的建模方式，与「不限运力、车型由成本决定」的假设之间存在冲突，导致原本的求解结果无法复现。把它改成路线局部槽位的结构之后，变量规模缩小了约 15 倍。这件事反复提醒我：**建模方式的分寸，往往比求解器的参数更决定结果。**

## 我为什么开始写工程笔记

同一段科研经历还给了我另一个教训：**只会算是不够的。**

真正让一个优化项目能被别人用起来、能长期维护下去的，是它外面的那层工程结构：依赖锁定、自动化测试、静态检查、持续集成，以及说得清楚的英文数学模型文档。所以我逐渐把「**复现 → 发现缺陷 → 修正 → 验证**」固定成自己的工作流程，重要修改都配上回归测试。

## 这里会写什么

- **运筹优化与算法**：建模思路、算法实现、实验设计与对比；
- **Python 工程化**：项目结构、测试与依赖管理、可复现实验的搭建；
- **机器学习与深度学习**：学习过程中的笔记与实践；
- **AI Agent**：本地 Agent 如何操作真实系统、工具调用与自动化排障这类主题；
- **排障复盘**：那些把我折腾到深夜、但事后值得留下记录的问题。

文章用 Markdown 编写，风格上尽量保持简单、清晰、可维护——能说清楚的事情就不绕弯子，不确定的结论会说明它的证据边界。
